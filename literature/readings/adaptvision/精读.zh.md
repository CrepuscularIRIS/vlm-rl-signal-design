# AdaptVision（Lin, Liu, Yang, Tao, Ye；Tencent Hunyuan；arXiv 2512.03794v2）精读

页码为 PDF 页。‡ 表示从图中读出或我自己算的数，说明见 SOURCE.md。

## 一句话
AdaptVision 让 Qwen2.5-VL-7B 先看 1/4 分辨率图，再决定直接回答或调用一次裁图工具取高分辨率区域；训练用 DTPO，把「工具 token」和「答案 token」分开归一化，并分别算优势后相加（λ=0.3），成本以视觉 token 比例计。

## 问题与设定
- 问题：VLM 视觉 token 太多；静态压缩方法按固定比例丢 token（§1，p.1–2）。目标是让 VLM 为每个样本自主决定最少的视觉 token（论文问句："minimum number of visual tokens required for each sample"，摘要 p.1）。
- 输入 x = {x_sys, I_low, q}，I_low 为 1/4 分辨率，视觉 token 只占 25%（§4.1，p.3）。
- 每个样本只有两种轨迹（Eq.5）：直接回答；或第一轮输出 `<tool_call>[x1,y1,x2,y2]</tool_call>`，拿到从原高分辨率图裁出的 I_crop，第二轮再推理并回答。结论部分写明 "maximum of two turns" 与 "a single visual tool and a fixed initial compression ratio (1/4 resolution)"（p.8）。
- 成本：n_img = n_low + 1_tool · n_crop；表 1 的 #Token 是相对原模型的视觉 token 比例（p.3、p.6）。文中未提 SFT/冷启动（只写了用 veRL 做 RL；"纯 RL" 是我的读法）。

- 论文自己指出的 GRPO 两个问题（p.5）：一是 "Ambiguous credit assignment"（信用含糊），决定是否取证的 token 与生成最终答案的 token 共用一个序列级奖励，例如裁图正确而答错时，答案 token 仍可能得到正向奖励；二是 "Imbalanced optimization"（优化失衡），两轮的工具调用序列在逐序列归一化下，工具 token 的梯度被压低。DTPO 的两处改动分别对应这两点。以上是作者的陈述，论文没有把两处改动分开做消融。

## 方法
**奖励（作用在任务奖励）**，R = R_oc + R_tool（Eq.6）：
- R_oc = R_acc + R_form + R_bal。R_acc 为 GPT-4o 判最终答案 0/1；R_form 格式合规 0.5；R_bal（Eq.7–8）：工具调用且答对 −0.1；直接回答且答对、同时组内 r = C_direct/(C_direct+C_tool) < θ=0.2 时 −0.1（针对 "lucky guesses"）。
- R_tool = R_crop − α·R_area，α=2（Eq.9）。R_crop 由 GPT-4o 判裁图是否含回答问题所需的主体（Table 5："check for presence, not completeness"）；R_area = I(R_acc=1)·I(R_crop=1)·clip(r_a/μ_a − 1, 0, 1)，μ_a 为组内「答对且裁对」样本的平均面积比（Eq.10）。直接回答的 R_tool 如何取值，论文未说明。

**DTPO（作用在信用分配 + 损失归一化）**：
1. 损失按轮次拆分（Eq.12）：工具 token 项除以全组 ΣT_i，答案 token 项除以全组 Σ(N_i − T_i)。作者指出 GRPO 的 1/N_i 与 1/G 使工具 token 梯度被压低（Eq.11）。直接回答 T_i=0，其全部 token 属答案项。
2. 优势拆分（Eq.13–14）：A_oc 与 A_tool 各自对组内 G=16 个 rollout 做 (R−mean)/std。直接回答：A = A_oc + λ·A_tool（全部 token）；工具调用：A = A_oc + λ·A_tool·I(1≤t≤T_i)，即工具 token 得 A_oc + 0.3·A_tool，答案 token 只得 A_oc（我对 Eq.13 的读法）。
- 论文给出 G=16，未提额外 rollout 或辅助损失；按奖励设计（R_acc、R_crop 由 GPT-4o 判）推断，额外开销是 GPT-4o 评分调用（我的读法，论文未列为开销）。

训练数据取自 VisionThink-Smart-Train（Yang et al. [37]），含两类样本：可用低分辨率图直接回答的，和需要高分辨率图才能准确回答的（原文："can be answered directly using low-resolution images ... require high-resolution images"，p.6）。规模、过滤、mask：论文未说明。超参：batch 512、mini-batch 32、lr 1e-6、G=16、温度 1.0、训练 80 步、4 节点×8 H20（附录 A.2，p.11）。

## 与我们的关系
**导读问题：其工具／答案信用怎样用于我们的多次观察，哪些信息条件不同？**

论文做了什么（事实）：把一条轨迹的 token 按轮次分成「工具 token（决定是否取证＋bbox）」与「答案 token」；工具 token 在结果优势 A_oc 之外多得 0.3·A_tool，A_tool 来自 GPT-4o 判的裁图相关性减去面积惩罚；答案 token 只得 A_oc。

简短回答：它的「工具信用」是把第一轮取证决定单独拿出来，叠加一个来自外部评判器的相关性与面积信号；「答案信用」仍是共享的结果优势。按我的读法，这套分法利用了「最多一次裁图、两轮」的结构，直接按轮次切段；下面逐条写出与我们设定不同的信息条件（各写事实，不排序）：
- **起始输入**：它从 1/4 分辨率图开始，工具取回原图高分辨率裁剪；我们的设定中每轮写 `<grounding>` 或 `<answer>`，裁剪返回高分辨率图，首轮输入分辨率本工作包未给出。
- **工具次数**：它至多一次裁图（我对 Eq.5 的单个 I_crop 与 p.8 "maximum of two turns" 的读法），因此「第一次决定」和「全部取证」是同一段 token；我们的设定允许多次 `<grounding>`，首次与后续裁图需分开记账。
- **成本口径**：它用视觉 token 比例（n_low + n_crop），不计生成 token；我们的账本是每题裁图数（首次/后续分开）加总处理 token。
- **信号来源**：它的工具信号来自外部 GPT-4o 对裁图是否含问题主体的评判，与最终答案对错无关（R_area 才与答对绑定）；我们的奖励 Y∈{0,1} 只看最终选项，可选 R = Y·(1 − λN)。
- **路线对比的取法**：它在同一 prompt 的 16 个 rollout 组内，用答对的直接回答与答对的工具调用的计数比 r，对 "lucky guesses" 加罚（只在组内统计，无分支重采样）；我们计划的首动作实验是从同一前缀分出「现在作答」与「先裁图再继续」两支各约 4 个 rollout，用回报均值差监督首动作。
- **直接回答的位置**：Eq.13 中直接回答的所有 token 获得 A_oc + λ·A_tool，其不裁图的决定不单独成段；决定与答案在直接回答里同属一段。
- **规模**：7B、80 步、batch 512；我们为 4B、一次过 6,016 题池（约 47 步）。
