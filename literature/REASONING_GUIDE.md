# 学习论文如何从现象走向算法

这是后续阅读的问题框架，不是本仓库已经完成的新一轮精读。各论文真实核查状态仍以[文献索引](README.md)为准。

每次选能帮助当前问题判断的少量论文，不要求把13篇全部读完才能推进。阅读时记录下面的推导链，并给出章节、公式、图表或代码位置；找不到支持就留空或标待核。

| 环节 | 要核对什么 |
|---|---|
| 现象 | 作者实际观测到的行为、统计或反例是什么？条件和分母是什么？ |
| 问题界定 | 作者如何把现象变成一个具体问题？哪些替代解释被检验，哪些没有？ |
| 假设与目标 | 目标量是什么？所需信息是否可得？依赖哪些环境、模型或采样假设？ |
| 算法步骤 | 哪一步对应哪个问题？为何采用这一比较、估计量或信用分配位置？ |
| 证据 | 哪个消融或对照支持该步骤的作用？总分提升是否足以支持作者的机制解释？ |
| 代价与边界 | 增加哪些采样/前向/标签成本？在哪些条件失效或尚未测试？ |
| 迁移问题 | 我们出现的是同一种现象吗？协议、模型、状态定义与可得信息有什么差别？ |

不要把论文成稿的叙述顺序声称为作者真实发现过程。明确区分作者陈述、实验证据和读者重建；有吸引力的想法也可能缺乏机制消融。

对“算法臃肿”的检查应落实到具体组件：作用是否重叠、是否引入额外假设、收益证据是否与成本相称。没有移除或替换证据时，只能提出简化问题，不能宣布该组件多余。相反，一个复杂组件可能解决了真实约束，简单不等于删除所有结构。

回到我们的问题时，先写它帮助澄清了哪个疑问、还不能解释什么；不要立即把多篇论文模块拼成新方法。下一步只推进当前有依据的一处推导。
