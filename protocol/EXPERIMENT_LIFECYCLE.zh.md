# VLM-RL 实验从立项到发布

每个新工作包拷贝下表。一行只有在验收人能打开证据、复核数值后才标「完成」。其余状态用「待做」「进行中」「阻塞（具体缺口）」「不适用（理由）」。每行登记负责人、日期与时区、证据位置、下一动作。上轮未决事项在下轮开跑前逐项处置；复用已验收产物时记版本。阶段顺序用于同一工作包，不改变已单独获准的并行任务。

| 阶段 | 执行与交付物 | 验收后进入 |
|---|---|---|
| 1. 研究问题 | 从最新导师要求和真实失败轨迹写出要教会模型的行为、最接近的已有办法、竞争解释、能区分它们的观察。原话、团队猜测和已获准的实验分列。 | 已有轨迹能回答就离线复核，缺新证据才写训练方案。 |
| 2. 数据与权限 | 冻结题池版本、来源、训练／开发／评测题量。用原图族及其派生 crop 查重，披露 SFT 与 benchmark/E1 已知重叠。检查图片解码、维度、坐标、选项与 GT；错标、歧义、静态不可判保留独立标记。 | 留下 split 清单、版本哈希、重叠表、允许的训练用途和公开字段。 |
| 3. 标注、SFT、testbed（按需） | 冻结 L0 可答性、L1 单位与正证据、L2 角色／值的口径，写明缺标 mask 和负证据。小批校准，看原图和叠框；按角色配对比较 IoU、漏框、多框、转录和单位。分歧盲审并保留未判定。示范、恢复前缀、负例各自记录来源、哪些 token 可监督。 | 交标注说明、校准表、失败卡、适用题数与数据版本。评测材料留在评测侧。只有需检验新能力时再设计独立 testbed。 |
| 4. 对照与预算 | 列全条件表：base／A-SFT 各自直答、CoT、原生工具；无工具与 caption 接口分列；base／A-SFT + outcome-only GRPO；DAPO、GSPO、GiGPO 等优化器及相应控制、已评外部模型。记录历史 6k/8k、续训、适配版、外部原协议的差异。 | 已评条件复用；缺条件标未测。写清单变量、初始化、题组大小、seed、目标步数、clip、学习率、KL、奖励、过滤键与采样上限。预算同时记生成／保留轨迹、唯一题、token、GPU-hours。 |
| 5. 离线机制检查 | 用同题真实兄弟样本检查组内区分、证据针对性、盲扫／重复／错引等反例和成本方向。先冻结预期方向，分别记原输出和构造样本。 | 记录通过／失败的反例，失败时限定可测问题，保留原公式和旧结果。 |
| 6. 实现与日志验收 | 在真实数据通路验证 group UID、Y／复合奖励、过滤、优势的 std/epsilon/尺度、assistant mask、事件位置、loss 分母。将真实送入 actor 的首批张量独立逐元素复算。双 rank 在非零学习率下核 loss、梯度与权重变化。首次训练前试读一个完整日志记录，确认 reward、entropy、diff 等预定曲线的字段、单位、参考量和聚合方法。 | 全同奖零梯度只说明该批缺信号。对事件版做“总奖励相同、事件位置不同”的反例；单 rollout 核按轮 V/Q 边界。未测指标提前登记。 |
| 7. 资源准入与一次派发 | 核对任务授权、GPU UUID、显存、进程归属、队列／锁、共享内存、磁盘与并行作业未来保存／合并峰值。冻结代码、输入、原模型指纹，独立 tag/attempt/目录。从原起点启动正式实验，或明确写出完整恢复点。 | 两实际 worker 读到冻结配置，生成、保留、更新齐全后才验收完整首步。具体卡号和保护线随工作包冻结。 |
| 8. 运行、故障与恢复 | 按授权频率记 Runner 完整步、数据供给、混合／零信号组、每 rank 事件、Y 与 R、验证、裁图／token、分段耗时与资源峰值。SSH 失联写最后可信时刻；故障留状态／日志，复核进程身份后只修本任务。 | 恢复核两 rank 权重、优化器、额外状态、dataloader 及 tracker；权重续接、优化器重置和完整恢复分别标记。原失败／丢弃分支单记成本。 |
| 9. 训练终点与固定评测 | 核退出码、完整步数、每 rank 实际更新数、有限损失和梯度、最终 checkpoint 文件及 tracker。固定最终 step，检查已有评测再派发，记录合并模型、题池、代码、采样及评分器指纹。 | 当前 E1 为 552 题 × 4 次，核 2,208 个唯一键、同键同 GT 同来源；保留错误和截断分母。近零分先查 prompt 的输出约束、真实终答及解析规则。 |
| 10. 定量比较 | 用同一评分器重算总表、四来源表、同键四格表和裁图分层。报告新增／失去正确数，核净差和分层总和。零裁、首裁、后续、重复、协议错误、截断、生成／处理 token 分开。 | 训练动态、开发验证、固定 E1 分列。若报告不确定性，按题聚类，注明训练 seed 数；增加 seed 和扩大预算依照当次获准方案。 |
| 11. 逐图审查 | 出分后按冻结规则选新增／失去、双错、答对但证据可疑、高成本等样本。配对看完整题面、原图、每个实际执行且可见的 crop、逐轮输出与终答。记录对象／角色／值／单位、首次可核验偏差、后续修正、未判定与成本。训练侧额外对齐奖励与实际 advantage。 | 有 manifest、有逐条 findings、有已审／待审数；结论回到原图与已给模型的视图。正文取 1–2 个可解释的正反案例，并注明定向选择范围。 |
| 12. 画图与复算 | 执行下方出图清单。从同一份表生成 PNG、PDF 和报告数值，保存脚本、输入表、来源与重画命令。 | 图、文、数据的终点、单位、排名和条件数一致；人工打开生成图片检查。 |
| 13. 导师稿与 GitHub | 导师稿按三部分交付：① 本轮设置及 SFT/RL 变更；② 1–2 个案例和定量结果；③ 训练 log、reward、entropy、diff 曲线及缺测说明。已获准范围内一次整理两仓，见下方发布清单。 | 留下两个仓库的 commit、可点击的图／报告、验证命令和结果。只完成本地文件时登记「待发布」。 |
| 14. 归档、交接与下一组 | 对照原问题写下事实、团队猜测、反例及未决点。封存源数据和指纹，依授权释放旧权重，须保留的归档逐文件核 SHA 后释放。更新队列、成本、控制记录、人工／自动监控归属和接手行。 | 先用现有证据解决待审项；下一项已获准且满足前置条件就推进。新问题、新预算或阶段选择由负责人决定。 |

## 如何执行这张表

- 接手时填入第一项未完成工作的负责人、输入、下一动作、验收人、需要交付的文件和停止点。设计与人审设置、关键代码、代表样本按现有分工交接，人审和工具复核分别记。项目负责人保留改变科学目标和预算的决定。
- 已授权流程内，前一项通过即推进下一项，包括 E1 后的轨迹审查、出图与双库发布；无需等待逐项提醒。若已交给用户手动监控，沿用该分工，不自行恢复定时任务。
- 候选机制注明证据作用于数据、奖励、优势还是辅助损失，比较从哪个状态出发、读取什么信息、分给哪些 token，额外前向或分支 rollout 如何计费。SFT 阶段分别登记生成库存、自动合格、真实抽审、获准入训四个分母。
- 人工检查尚未回执、数据分发权不清、未覆盖的 baseline 或未回传日志，保留为显式缺口。一轮允许出现负结果或未测指标。若旧要求与新口径冲突，留原条款、最新授权、所用版本及取舍；仅因更近或写着“完成”不足以证明已验收。
- 资源有约束时优先现成数据和最小判别测试。取消、暂缓、失败和正常结束各写明终态；已授权归档先校验本地和源端逐文件 SHA，再释放指定副本。研究报告、公开发布、清理磁盘分别结账。

**图的交付检查**：图名和标题能识别实验及口径，轴、图例、分母可读；重画命令只读公开数据，在临时目录验证 PNG/PDF 都能打开；报告嵌图并链接 CSV/JSON 和脚本。历史基线展示集合按工作包冻结；退役条件在档案可查。相同摘要不手抄多份，README 的“最高／最省”等描述须用全表反查。

## 两个 GitHub 仓库各交什么

1. **设计库**：每轮建一个版本化结果目录，含设置和算法差异、定量表、同题案例、训练图、E1 成本图、可复算表和 provenance。将它链接到 README 与 START_HERE；涉及设计、协议或可复算边界变化时同步对应页面。导师稿三部分见阶段 13。
2. **轨迹库**：README 指向总览；docs/01 更新实测结果、代表图和设计库报告；docs/02 写协议差异、失败／未判定、案例范围及证据限制。已授权的公开轨迹才导出脱敏记录。汇总与图表尽量链接同一结果包。
3. **推送前**：从干净的暂存范围核对新旧表、计算分母和配对、重画图、检查所有新增相对链接及图注，扫题面、原图、私人通信、机器路径、凭证。header 可发布字段白名单及原始文件 SHA；不得把配置哈希标成模型权重哈希。已有历史错误用有来源的修订说明，保留版本。
4. **推送后**：核远端分支包含两个 commit，并从读者入口走通“README → 结果 → 图 → 数据／脚本”。检查 CI（如有），分别登记推送、产物验证、CI 的状态。论文图、README 与导师稿引用同一版本。没有结果、无权分发或确实缺测时，明确缺哪一项、谁接手、怎样补。

每轮建议保留一张收尾表，列为「阶段｜应交文件｜本次文件或链接｜通过／缺测／待做｜负责人与下一动作」。对性能暂不领先的实验，照样交付分母、成本、案例、曲线和失败条件。[当前评测口径](CURRENT_PROTOCOL.md) · [复算入口](../REPRODUCIBILITY.md) · [DTPO 实例](../results/dtpo_e1_20261103/RESULTS.zh.md)
