# 分轮推进建模讨论

目标是从实际现象逐步明确问题，再推导简单的方法。当前未选定统一瓶颈，也未选定下一算法。多个问题可能交织，但不能据此把每个错误都变成一个奖励项。

## 第一轮：现象、竞争解释与候选gap

先比较同题得失、来源差异和实际轨迹：哪些现象确实发生，哪些只是总分或曲线引出的猜测？终答、观察内容、决策、协议执行分别保留证据；不要从E1错答反推训练梯度。

选与当前问题直接相关的论文，按[论文推导阅读方式](../literature/REASONING_GUIDE.md)学习它如何从现象提出问题。区分作者原文、论文实验支持和我们对推导过程的重建，不照搬其问题定义。

这一轮输出几个候选gap及竞争解释即可。gap先指当前尚未解释、测量或区分清楚的问题；不是未经文献核对的“别人都没做过”。说明哪个问题最值得下一轮聚焦，以及理由。允许暂时不足以选择，但不要泛读到所有未知都解决才继续。

**本轮停止点：与研究者选定下一步要解释的问题。不要同时要求完整算法、损失公式和新实验方案。**

## 后续轮次：随问题逐步展开

1. **明确问题与目标。** 在哪个场景、哪个决策点发生什么可验证失误？希望改变什么行为，如何判断改变？哪些情况仍是基础感知/推理或接口问题？
2. **检查现有算法的步骤。** 每个组件在估计什么量、依赖什么信息、把信号给谁、增加多少计算？已有消融支持它的哪个作用？“算法可能臃肿”是待检验判断，不能只按组件数量或公式长度下结论；移除组件的影响未知时写未知。
3. **推导最小改动。** 问题明确后，从一个必要的算法步骤开始：若讨论advantage或credit assignment，先定义状态、比较对象、估计量和信用接收位置，再写公式。沿用已有合理部分，避免为每种失败叠加模块。reward shaping是否必要留到这里判断。
4. **检验与取舍。** 设计具体后再提出能区分解释的最小测试，列出反证结果、实际成本和可比性。准确率容忍delta与新预算由研究者决定，不自动改协议或启动训练。

这些是讨论顺序，不是必须一次交付的清单。每轮只推进一个清楚的问题，保留其证据、假设、未决项和下一步；新的证据可以要求回到前一步。

拒答、幻觉惩罚等保留为后续可能方向，不以尚未定位的现象直接论证其必要性。公开材料没有原图和E1到训练梯度的逐条映射；不能用模型自述填补。当前任务是讨论资料整理，不发起新咨询或实验。
