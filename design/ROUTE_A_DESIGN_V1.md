## 0. 研究问题与三层分工

> 在固定短 caption 协议下，条件化 hint 能否促使模型**补做缺失的证据操作**，并**减少跨轮的身份 / 角色错绑**？证据条件满足后，模型能否**及时停止**？

三件事分开做，不全塞进 reward：

| 层 | 职责 | 对应 Bridge §9 |
|---|---|---|
| hint | 帮模型**采到**值得学习的操作，用法是 H1：作为条件输入 | 原有 hint 库 |
| 标注 + 证据状态 | 判断操作是否真的**获得并保持**了证据（审计） | I 图结构、J 显式记忆、A / C / G 降低标注成本、D 做检验 |
| GRPO | **强化**这些操作；终答奖励不变；通过审计的过程信号再加入 | H（BPTT 类比）只落在事件级信用上 |

**优先级**：P1（H1 + 证据状态审计）> P2（通过审计的 bbox / 证据过程信号）> P3（事件级信用分配）。

**框架**（研究者对 Primitives 机制的归纳，不是论文里的命名）：

**适用条件 → 指向的证据对象 → 允许的状态更新 → 完成条件**

## 1. 从 Primitives 借什么、不借什么

**借：**
- **操作要有明确对象，状态要有依据。** 不同任务需要不同的证据操作，例如粗计数是批量框出后汇总，细粒度题是逐个候选核对条件并记录排除理由。不是所有题共用一个写法模板。
- **前提错了，依赖它的结论就失效。** 但不照搬“出错一次，后面全部清零”：
  - 表格题纠正了列绑定，只撤销旧列下的读数和比较；其他行已经正确读出的事实保留；
  - 换了候选，旧候选的属性不能带到新候选上；
  - 不为“发生了一次修正”额外加分。
- **何时启用某种行为，论文没有解决**（局限 2）。在我们这里，就是模型能否在缺某个证据条件时**自己**去补查。

**不借：** 特殊 token、在思考里写点和框、绘图工具、预训练、OPD、LLM 质量评审进入奖励。

**收紧 Bridge 里的四处类比：**
1. **视图引用 ≠ 实体指代。** 一张视图可以包含多个候选，引用对了视图，仍可能绑错对象。
2. **硬检查终止 ≠ 迷宫的因果截断。** 硬检查只管接口和格式；格式合法的轨迹仍可能从错误事实接着推下去。
3. **不裁图 ≠ 跳过证据。** 原图本身就可能足够清楚，足以作答。
4. **像素网格的邻接关系 ≠ 任务的依赖关系。** 证据图应该建在“角色和候选身份”上，不建在均匀划分的网格上。

## 2. P1-a：H1 hint 探针（推理，不训练）

**目的**：同一个 checkpoint、同样的预算下，hint 能否改变**动作**和**正确率**，而不只是让 caption 写得更像规范。

### 2.1 条件

| 条件 | 首轮 prompt 的区别 |
|---|---|
| `none` | 现有 prompt，和 RL / E1 相同 |
| `matched` | 按标注单位选出的 hint，原文取自协议 `HINTS`（规则见 §2.3），以 `\nHint: …` 的形式插在题面之后；这正是教师生成 SFT 时用的格式 |
| `neutral` | 字数和 `matched` 接近、但不含任何操作信息的中性提示，用来扣除“prompt 变长”本身的影响 |

可选的第四个条件 `mismatched`：故意给错的 hint 类型，检验模型是不是真的在执行 hint 描述的操作。

### 2.2 题目与 checkpoint

- **题目**：从 1,399 道补充验证候选中按单位分层抽题。这批题的原图不在 4K 训练池里，但属于旧 6K 训练池；按图像聚类计算误差（见 `VALIDATION_AND_CONTINUATION`）。
  - 只取 P1 关心的两类：表格 / 图表的角色绑定，以及相似候选消歧（`keyed_set`、`multi_compare` 和带干扰项的 `single_box`）。
  - 建议每类 100–150 题。抽出的题按 [ANNOTATION_SPEC](ANNOTATION_SPEC.md) 标注（v2 字段见 §4）。
- **不用 E1。**
- **checkpoint**：A-SFT（RL 之前的行为）和 k8 DAPO 第 32 步（最强 baseline）。
- **采样设置**：每题 4 次，与 E1 相同（temperature 0.7、8 次裁图、max_px 589,824）。

### 2.3 hint 选取规则

按**标注单位和角色**来选，不用正则（正则和看图结果只有 66/163 一致）：

| 标注单位 / 情形 | hint key |
|---|---|
| keyed_set（表格） | `table` |
| keyed_set（图表） | `chart` |
| multi_compare、带 negatives 的 single_box | `instance` |
| pair_relation | `relation` |
| 目标是小字的 single_box | `text` |
| 原图长边 ≥3000 px | 额外加 `search` |

每题最多 2 条，和教师生成时一致。

可选的“针对失败类型改写的 hint”（Pro 给的两个例子）作为**第二版**，先用协议原文，免得 hint 文本本身成为一个新变量。

### 2.4 观测指标（每题 × 条件 × checkpoint）

| 类 | 指标 | 计算方式 |
|---|---|---|
| 结果 | 准确率；按图聚类的配对差（matched − none、matched − neutral） | 现有评分器 |
| 动作 | 裁图次数；首裁位置；是否有某次实际执行的视图覆盖了每个证据节点（覆盖 ≥0.9） | `boxes_abs` 与标注框 |
| 可读 | 证据节点在呈现视图中的像素尺寸，例如文字行高 | 环境的 `present` 规则可以算出 |
| 状态 | 证据状态审计结果（§3） | 审计 |
| 表达 | caption 是否提到行键 / 列键 / 候选区别 | 只作描述，不作为结论 |

**三种结果的读法**（来自 Pro）：

| 结果 | 含义 |
|---|---|
| 只有 caption 变了，动作和正确率不变 | hint 影响的是表达，不足以作为学习依据 |
| 有效动作增加，正确率也上升 | 支持 H1 课程；仍需做无 hint 迁移评测 |
| 证据已经获得，但仍然读错或绑错 | 奖励不能只放在 bbox 上，要看获取之后怎么使用 |

### 2.5 实现

- **只改数据，不改代码**：生成三份评测 parquet，区别只在 `env_head`。hint 用 `caption_v51.first_user_text(question, hint_keys, …)` 生成，和教师当年的格式完全一致。
- 评测用现有的 `eval_caption.py` 和 `summarize.py`。

## 3. P1-b：证据状态审计（离线，不进奖励）

### 3.1 状态

在每一轮 t 之后，记录：

> M_t = (F_t, D_t, U_t)

- **F_t**：当前有依据的事实及其绑定。每条记为（实体 / 候选，角色，值或属性，支持视图，状态）。
- **D_t**：有依据地排除掉的候选或分支。
- **U_t**：还没解决的条件，由标注的证据节点和绑定元组减去已解决的部分得到。

这是**审计用的状态**，不声称读出了模型的内部状态，也不喂给模型。

### 3.2 每条轨迹的错误定位

按下面顺序判断第一个失败点：

1. **未获取**：没有任何实际执行的视图覆盖必要的证据节点。
2. **获取但不可读**：节点被覆盖了，但呈现尺寸不够看清。
3. **读错**：caption 里的转录或属性与标注不一致。
4. **绑错**：值读对了，但属于另一个行、列、系列或候选。
5. **未保持**：前面绑对了，后面被覆盖掉，或换候选时继承了旧属性。
6. **映射错**：事实都对，选项映射错了，例如 CALC 的结果和最终选项对不上。
7. **停止问题**：证据已经充分还继续裁图（多余），或证据不足就 commit。

- 第 1、2 步可以用程序判断（`boxes_abs`、标注框、`present` 尺寸）。
- 第 3–6 步需要从 caption 里抽取断言。先用**冻结的评审模型，配合标注和图像**，在小规模审计集上做；判断不了的标记为“未判定”，不硬给结论。
- 第 7 步可以由第 1–4 步的状态推出来。

### 3.3 对候选过程评分器做反事实审计

从真实轨迹出发，**只改 caption 文本**，构造以下变体，检查候选评分器会不会给它们高分：

| 变体 | 期望 |
|---|---|
| 数值不变，交换行键和列键 | 绑定分下降 |
| 属性不变，换成另一个候选 | 绑定分下降 |
| 引用一个确实存在、但不支持该断言的视图 | 不得分 |
| 把同一个清楚的数字重复确认一次 | 不加分 |
| 先写一个错的断言再 REVISE 成对的 | 不比一开始就写对得分高 |
| 整图裁剪 / 网格扫图 | 几何项不能接近满分 |

只有通过这组审计的评分器，才能进入 P2。

## 4. 标注规范 v2 需要增加的字段

**已落实**：2026-11-01 发布 [ANNOTATION_SPEC v2](ANNOTATION_SPEC.md)，改为 L0 / L1 / L2 分级标注，下表字段全部纳入。

P1-b 的第 3–5 步要用到下列字段，v1 里没有。没有它们，“读错”和“绑错”就分不开。

| 字段 | 内容 |
|---|---|
| `value` | 每个证据框读到的内容：转录文字、数值、颜色等，含单位和必要的脚注 |
| `bindings` | 必要的绑定元组。表格：（行键，列键路径，值，单位）；图表：（图例，系列，面板，轴，读数）；实体题：（候选，归属条件，属性） |
| `evidence_sets` | 充分证据组合，可以有多组；用于判断“多条合法观察路线” |
| `distinguishing_condition` | 干扰候选和目标的区别，写成一句可以核对的话 |
| `answerability` | 区分“目标不存在 / 当前看不清 / 题目本身无法回答” |
| `annotation_confidence` | 高 / 中 / 低 |
| `provenance` | `independent`（逐题看图独立标注）或 `pseudo_*`（来自教师框、成功轨迹、OCR、检测器的候选）。两类分开存放，不混在一起 |

## 5. P2：H1 课程训练，以及通过审计的过程信号

### 5.1 H1 课程（只有在 P1-a 出现“有效动作增加、正确率上升”时才做）

- **起点**：A-SFT。**奖励**：不变（终答 0/1）。**优化器**：与对照组相同。
- **数据**：每题指派一个条件（hint 或 none），同一组内的 8 条轨迹条件相同。hint 写进 `env_head`。由于 prompt 是从 `env_head` 现场构造的（`easyr1_caption.py:86`），**采样和计算策略概率用的是同一个带 hint 的上下文**，不会出现“生成时有 hint、更新时删掉 hint”的错配。
- **hint 比例**：最简单的方案是两段式，前一半步数用 p_hint，后一半步数用 0。逐步递减的方案需要预先按采样顺序生成题池。p_hint 的取值由研究者定。
- **对照**：同起点、同步数、同题池、无 hint 的 GRPO 或 DAPO。主指标是**无 hint 输入下**的表现，不能用带 hint 时的成功率推断。
- **要说明清楚的一点**：H1 改变了训练分布，属于带条件的课程学习，**不是**和原目标等价的替换。

### 5.2 过程信号（只有在 §3.3 审计通过后才做）

- 奖励形式：R = V·[Y + λ·m_q·Φ]。
  - V 是硬检查；Y 是终答；m_q 表示这道题的标注是否适用、是否可靠；Φ 是证据完整度（mean + min 聚合）和绑定正确度。
  - 原图已经足够清楚的证据也要算进去，不能只给新增的裁图计分。
- **λ 会被组内标准化抵消**，所以真正的设计变量是**哪些组让 Φ 起作用**，以及 DAPO 按什么过滤：现在 `filter_key=overall` 会把复合奖励也纳入过滤，按准确率过滤应改成 `accuracy`。
- **导师的 gate**：按组切换。同组 8 条里只要有一条拿到了必要证据，就用证据和绑定信号；否则用“有依据的候选排除”信号。不用裁图并集的面积。

### 5.3 对照矩阵（同起点、同题池、同步数）

| 组 | 改动 |
|---|---|
| 0 | 原 baseline（终答） |
| 1 | + H1 课程 |
| 2 | + 纯几何过程项（导师原式） |
| 3 | + 证据 / 绑定过程项 |
| 4 | 1 + 3（只在两者分别有效时才做） |

成本单独记账：hint 带来的额外 prompt token、评分器的前向计算、验证、存档，都要分开报告。

## 6. P3：事件级信用分配（只在 P2 的评分已经可靠、但仍明显信用错配时才做）

- **出处**：DeepSeekMath §4.1.3 的过程监督 GRPO。在步骤末尾给过程分，把后续步骤归一化后的奖励累加到对应 token 的 advantage 上。优化框架仍然是 GRPO，但 advantage 计算、步骤边界、归一化和 mask 都要改，需要单独做对照。
- **只在可核验的证据事件上给信号**，例如“必要节点首次变得可读”“绑定建立”“绑定被正确撤销”，不在每一轮都做价值估计。
- **不截断回看窗口**：跨轮的身份绑定可能依赖很早的观察。省成本的办法是减少评估的事件数，而不是缩短依赖链。
- **不重复 SP / CA**：它们用每个估值点 K=4 次续写来估计终答均值。在成功率 0.5 附近，两个均值之差的标准误约为 0.35（理想化计算），分辨不出几个百分点的局部差异。
- **BPTT 的定位**：只保留“后面的错误可能来自前面的绑定、前面必要的观察可能要到后面才显出价值”这个思路；不做可微环境，也不换循环架构。HOLD 是模型生成出来的显式工作记忆，不是隐状态。

## 7. Bridge §9 候选的用途重排

| 候选 | 用途 | 不做的事 |
|---|---|---|
| A / B 教师框、教师共识 | 生成待复核的候选；定位标注分歧 | 不当作真值 |
| C / G OCR、检测器 | 加速定位、生成候选 | 不用“搜到了选项文字”代替独立标注 |
| D 遮挡 / 反事实 | 在少量关键案例上审计信号 | 不在每次 rollout 上做全图干预 |
| E 组内成功轨迹 | “成功轨迹辅助发现”：选样、找候选区域 | 不叫 HER；不把答对轨迹里的所有裁图都当正标签 |
| F 代理评分器 | 有了可信标签之后，再研究能不能降低验证成本 | 不先训练一个评分器，再让它定义什么叫进展 |
| H BPTT | 组织事件级信用（§6） | 不做可微环境 |
| I / J 图结构 + 显式记忆 | 证据状态审计（§3） | 不要求全量 scene graph，也不要求模型输出长记忆 |
