# 正式 RL 训练设定（formal_v1，2026-11-10）

本页记录 11-08 起的正式训练线：新的视图呈现规则（formal_v1）、重做的 SFT、重新筛选的 12k RL 数据池，以及按 Mini-o3 配方开始的第一组 RL 训练。11-08 之前本仓库里的结果都属于旧呈现口径（见 §1），这里的数字不能和它们直接比较。

## 0. 一页摘要

| 项 | 设定 |
|---|---|
| 硬件 | 4 × NVIDIA RTX PRO 6000 Blackwell Server Edition（单卡显存 96 GB），单机；容器内存上限 440 GiB |
| 学生模型 | Qwen3-VL-4B-Instruct |
| SFT | 现有 SFT 语料 4,034 题 / 7,041 个监督轮次，按新呈现规则重新渲染；全量微调语言模型，冻结视觉塔与 projector；2 轮，lr 1e-5 |
| RL 数据 | 12,000 题：DeepEyes 8,000（G1 3,000 + G2 2,000 + G3 3,000）+ VisualProbe 4,000（G4），比例与 Mini-o3 相同 |
| RL 算法 | Mini-o3 式 GRPO：组内标准化优势 + 动态采样（过滤全对、全错组）、clip .2/.3、token 级 loss、无 KL |
| 规模 | 每步 256 个题组 × 每题 16 条轨迹；actor mini-batch 32 组；lr 1e-6 常数 |
| 训练量 | 数据过一遍即停（12,000 题每题生成 16 条，各一次），按实测吞吐预计约 30 步、约 20 小时 |
| 奖励 | 只看最终答案对错的规则判分（0/1），不用 judge 模型，不加长度或裁图奖励 |

## 1. 为什么重做：视图呈现规则（formal_v1）

模型通过多轮“裁图 → 看局部 → 回答”作答。每看一张视图，环境会在回执里写一句像素说明，例如“原图 1500×1500，缩小到 94% 显示”。

11-08 核查发现，旧链路里这句说明与模型实际收到的图并不一致：环境先按自己的规则缩放一次，训练框架的数据加载器又按默认上限 589,824 像素再缩小一次，最后 processor 再做一次对齐。原图视图中有 85% 被二次缩小，回执里写的尺寸与模型实际看到的不同。这是几个默认值叠加造成的，不是有意的设计。

formal_v1 的做法是 SFT 渲染、RL 环境、评测三处共用同一个呈现函数：
- 原图和裁图都从全分辨率原图得到，裁图按回执中的归一化坐标从原图切出；
- 短边小于 448 时放大，最多 4 倍；
- 面积限制在 65,536 到 2,000,000 像素之间，2M 的上限与 Mini-o3 相同；
- 宽和高对齐到 32 的倍数（Qwen3-VL 的 patch 为 16，2×2 合并）；
- 回执里的像素说明按实际尺寸写出。

已核对的项目：
- processor 对新尺寸的图片不再做任何缩放：grid 等于 [1, H/16, W/16]；
- 训练框架分词后，每一行的图像 token 数都与按尺寸算出的值相同；
- SFT 文本除像素说明外，与原语料逐字相同。

## 2. SFT

| 项 | 设定 |
|---|---|
| 语料 | 现有 SFT 语料（V2.2 keep）4,040 题。其中 6 题的原图与原渲染内容对不上，无法重建，剔除后剩 4,034 题；按“每个监督轮次一行”展开为 7,041 行 |
| 方式 | 全量微调语言模型，冻结视觉塔与 projector（与 Mini-o3 相同） |
| 超参 | 2 轮（Mini-o3 为 3 轮），lr 1e-5，cosine 调度，warmup 0.1，有效 batch 48，cutoff 16,384（没有截断任何一行） |
| 框架 | LLaMA-Factory + FSDP2，4 卡 |
| 结果 | train loss 0.667，eval loss 0.700 / 0.697（第 1 / 2 轮）；用时 1.8 小时 |

同一套设定还训练了 Qwen3-VL-8B 和 InternVL3.5-4B / 8B（InternVL 使用官方动态切块：最多 12 块，另加 1 张缩略图）。这四个 SFT 模型在 E1（552 题 × 4 次采样）上的准确率：

| 模型 | E1 | V\* | MME-RealWorld | MMMU-Pro | WorldBench |
|---|---:|---:|---:|---:|---:|
| Qwen3-VL-4B | .688 | .895 | .724 | .321 | .351 |
| Qwen3-VL-8B | .717 | .933 | .732 | .423 | .432 |
| InternVL3.5-4B | .625 | .806 | .645 | .404 | .331 |
| InternVL3.5-8B | .633 | .815 | .653 | .391 | .347 |

## 3. RL 数据池：12,000 题

### 3.1 四个来源

| 组 | 来源 | 内容 | 答案形式 | 图像大小（中位数） | 主池题数 |
|---|---|---|---|---:|---:|
| **G1** | DeepEyes-47k · V\* 视觉搜索子集（自然图，源自 COCO2017） | 物体属性、颜色、左右 / 上下位置、是否存在 | 是非句、短句 | 0.19 M 像素 | **3,000** |
| **G2** | DeepEyes-47k · ArxivQA 子集（论文中的科学图表） | 读图例、读数、比较曲线和面板、简单计算 | 选项字母 | 2.46 M 像素 | **2,000** |
| **G3** | DeepEyes-47k · ThinkLite-VL 子集 | 计数、几何、空间关系、表格；部分题带 (A)(B)… 选项 | 数字、短语 | 0.10 M 像素 | **3,000** |
| **G4** | VisualProbe 训练集（Mini-o3 发布） | 高分辨率图中的小目标、文字识别、困难的视觉搜索 | 短语 | 17.7 M 像素 | **4,000** |

DeepEyes 三组内部的比例为 3,000 : 2,000 : 3,000。VisualProbe 与 DeepEyes 的比例为 4,000 : 8,000，与 Mini-o3 论文的 RL 数据一致。

| 抽样审核与替换 | 6.1 Sol 审核主池随机 280 题（各组 20 题，G4 另加 200 题），不是“保留”的题用同组候补替换 | 换 3 | 换 3 | 换 1 | 换 21 |
| **最终主池** | | **3,000** | **2,000** | **3,000** | **4,000** |

补充说明：
- 主池共 11,587 张不同的图。G4 里有 413 张图各出了 2 道题，两道题的任务类型不同。
- 另有同样经过筛选的候补题（每组约 5%），只用来替换坏题，不增加训练量。
- 看图验收的情况：筛选前，从初选清单每组随机抽 32 题，G1 有 14 题有问题、G2 有 15 题（多为指代不唯一、标答与图表读数不符）；筛选后，从主池抽查，未通过的为 G1 3/20、G2 3/20、G3 1/20、G4 2/20，G4 加审 200 题中未通过 19 题（剔除 4、看不清 15）。审核者是模型子代理，部分分歧题做了复核；每组样本量小，这些比例不能当作精确的错标率。
- 难度没有按模型做校准。0/16 全错的组是否属于错标，不能只凭训练结果判断。

## 4. RL 训练设定

### 4.1 配方（对齐 Mini-o3 §4.1）

| 项 | 我们 | Mini-o3 |
|---|---|---|
| 优势估计 | GRPO 组内标准化 | 相同 |
| 动态采样 | 开：过滤全对 / 全错组并补齐；过滤后不进入第二遍 | 开（rejection sampling） |
| 每步 / 每题 / mini | 256 题组 / 16 条 / 32 组 | 相同 |
| clip（下 / 上） | .2 / .3 | 相同 |
| loss 聚合 | 按全部有效 token 平均 | 相同 |
| KL / entropy | 都不加 | 相同 |
| lr | 1e-6 常数 | 相同 |
| 截断屏蔽 | 单轮超长、超出上下文、轮数用完仍未作答的轨迹，不参与更新 | 相同（over-turn masking） |
| 上下文 | 32K（prompt 4,096 + response 28,672；单轮最多 640 token） | 32K（prompt 8,192 + response 8,192） |
| 训练轮数上限 | 9 轮（最多 8 次裁图 + 作答，与 SFT 语料的预算一致） | 6 轮 |
| 温度 | 0.7 | 1.0 |
| 图像像素上限 | 2M | 2M |
| GPU | 4 卡 | 64 卡 |

### 4.2 奖励

只看最终答案对错（0/1），用规则判分：
- 选择题比对选项字母；题目带选项而模型直接答了字母时，先换成对应选项的文字再比；
- 是非题比对首词；“A 还是 B”类题看答案选的是哪一项；颜色题比对颜色集合；
- 其余题比对归一化后的内容词。归一化包括大小写、数字词、冠词，以及“a bunch of”这类量词短语。

不使用 judge 模型，也不加长度、裁图次数或过程奖励。格式错误（没有给出合法答案）记 0 分。

### 4.3 “过一遍”与训练量

“一遍”指 12,000 题每题生成 16 条轨迹，各生成一次。数据读完训练就停止，最后一步用已收集到的组训练。步数不提前固定，由动态采样实际保留下来的组决定。

## 5. 训练吞吐（4 卡）

已完成的前几步：

| 步 | 用时 | 生成 / 重算 old log-prob / 更新 | 本步生成题数 | 收集 / 使用 / 截掉的组 | 训练准确率 |
|---:|---:|---|---:|---|---:|
| 1 | 2,474 s | 1,074 / 378 / 1,014 s | 400 | 263 / 256 / 7 | .464 |
| 2 | 2,343 s | 1,033 / 329 / 971 s | 400 | 267 / 256 / 11 | .476 |
| 3 | 进行中 | | 480 | 307 / 256 / 51 | |

- 约每小时 600 题，过一遍预计约 30 步、约 20 小时（目标 18 小时，可接受范围 18–24 小时）。
- 主机内存峰值 293 GiB，显存峰值约 90–97 GB / 卡。

为了能在 4 卡上跑下来，做了以下工程改动，都不改变计算结果：
- 每次生成后把空闲内存还给系统：修复前主机内存曾到 433 / 440 GiB，worker 被杀；
- 同一题的 16 条轨迹，prompt 校验只做一次；
- 更新阶段的 micro-batch 设为 1：之前 micro-batch 为 2 时，长回答在反向传播中显存溢出；
- 只在回答位置计算 logits：与全量计算逐位比对，最大差为 0。

## 6. 还没弄清 / 待定的问题

- G4 有 51/200 的题，审核者认为严格的字符串匹配可能把等价的正确答案判错（时间格式、同义说法、方位用词）。判分规则还没为此放宽。
- 第 1 步的学习率是 0：warmup 为 1 步，框架在第 0 步取系数 0，所以第 1 步没有更新参数。
- 本次运行没有逐步的“进入更新的题目 ID”记录（日志包装的接线问题，已在代码中修正，下次运行生效）。覆盖情况改从生成日志按题目 ID 统计。
- 与 Mini-o3 不同的三项设置（轮数 9 vs 6、温度 0.7 vs 1.0、response 长度）暂时保持不变。
