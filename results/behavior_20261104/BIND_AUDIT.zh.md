## 2. Φ_bind 评分器（`obs/src/bind/`）

- **v1**：只看最后作答回合并剥离元数据；要求列路径完整（某一级单独出现不会和其他列混淆时可只写这一级，否则要求各级都写）；最后一个绑定分句中，离列标签最近的数字视为采用值；值框、行表头、列表头都必须在某个视图中可读；实体分支关闭。反例测试 15/15。
- **v2**（依据 60 条抽检修改）：每个数字归属到最近的行标签和最近的列标签，行、列都是目标的数字才算候选，取最后一个；标签匹配忽略空白差异；复合行名按 ` / `、` - ` 拆分；位于行名内部的列名不计；统一 Unicode 减号；支持 `.85` 这种写法。反例测试 20/20。
- 索引：v1 652 题 / 1,013 槽位；v2 655 题 / 1,038 槽位（只含数值型表格绑定）。

## 4. 按 Design_PH 判据的结果

- Design_PH §二要求：在 DAPO 保留的混合组里，同样答对的轨迹之间，B1 的差异应对应“绑定正确 / 错误”；如果只是格式不同、标签提及不同，奖励教的是表达，不是能力。
- 实测：
  - 混合组里，答对的轨迹之间 Φ 有差异：v1 172/290 组，v2 212/291 组；
  - 但被抽到的 30 条答对轨迹，人工判断全部写对了绑定（Φ>0 的 15 条和 Φ=0 的 15 条）。所以“答对的轨迹之间”的 Φ 差异，在抽检中全部来自评分器能否识别其写法。
- 答错轨迹中 Φ>0 的比例为 v1 .076、v2 .083。抽检中，Φ>0 的答错轨迹有 12/15 确实写对了绑定，但计算、选项或标注值不一致。混合组中，答错的轨迹之间 Φ 有差异：v1 29/214，v2 35/214。
- Φ 与裁图数、输出长度的关系（v2，答对轨迹）：0 / 1 / 2 / ≥3 张裁图分别为 .260 / .555 / .487 / .454；生成 ≤150 / 151–300 / >300 token 分别为 .683 / .521 / .418。
