# 导师要求：匿名技术整理

来源为项目提供的Conversation及2026-10-26～10-29用户转述；本页是技术性转述，不是完整聊天原文，也不是逐字引语。源文件SHA记录在provenance。个人身份、联系方式与私聊其他内容不公开。

## 目标与工作方式

- 根据中间观察和决策对完成任务的贡献，形成更有效的学习信号，改善性能与成本权衡。
- 方法尽量简单；伴随经验结果判断，不从纯公式分析直接宣布有效。
- 先补齐baseline、核对配置和实际轨迹，再讨论新方法。模型/代理的解释须与代码和原始证据分开。
- 视觉观测错误作为动机和结果观察维度，不要求每类错误分别加入奖励。它是否随训练减少仍要测量，不能当必然结果。
- 不做multi-seed是本轮项目资源安排，不代表训练随机性不存在。

## baseline要求及两种历史列表

早期四类11项口径：
1. 原模型direct、CoT、工具提示。
2. 原模型经2epoch SFT后重复以上三项。
3. SFT+标准outcome-only GRPO、原模型+标准GRPO。
4. 将GRPO替换为DAPO、GSPO、GiGPO。

后续明确扩展：原模型无工具、原生zoom、caption zero-shot分别报告；加入原模型+GRPO without tool、AdaptVision/CounterCredit等方法参考，以及Mini-o3、DeepEyes或Pixel Reasoner等外部比较。

因此不能仅凭“11项齐了”宣布后续全部要求已完成。当前数据有原模型/SFT多接口、旧6k与新4k等25条件；**AdaptVision/CounterCredit/Pixel Reasoner没有本次E1复现结果**。工具提示“不用function calling”曾有口径疑问；实际已跑接口见protocol，不强行把名称等同。

## 预算与结果报告

- 用户与导师最终选择本轮4,096题、128题/步、8 rollout、32步作为主要RL预算；此前追加训练另列探索。
- 导师关于RL样本过一遍的建议是本轮安排，不写成“任意RL只训一遍必收敛”的理论结论。
- DAPO动态补采使生成题组次、更新题组次、唯一题数不同，不能把32步称为精确一遍覆盖。
- max_grad_norm曾在讨论中出现0.1；本轮实际配置为1.0。梯度是否被clip和收敛是否充分是不同问题。
- 所有条件呈现在性能—成本图；首裁与后续裁图分开，加累计处理token。训练成本另列，不与测试推理成本混算。
- Base+GRPO仅为baseline。即便很低分，不为提高它的成绩专门改变协议、奖励、数据或超参数。

## 已提出的建模方向（不能混成两个已验证方法）

1. 干净RLOO对照：终答正确性乘裁图成本项，优势减去其余同题轨迹平均奖励。历史建议比较lambda=0/.01；本次v53配对均lambda=.01，不是这两个lambda的对照。
2. 四种工具分支关系：错→对关注有效观察；对→对不自动把功劳分给冗余工具；错→错不把必要但未成功的探索一律当坏；对→错关注误导性工具。这里是信用方向，未自动给出可识别的因果标签。
3. 先实现首动作分叉监督：同一前缀下分直接回答和crop后继续，两支各4条，用整条续写收益差监督动作标签概率。已跑v53 control/decision；BCE具体形式是项目实现选择，并非导师逐字规定。
4. 势能信用属于后续讨论，未实施。RLOO control与首动作监督是一个配对实验，不能当成“两种新方法都已完成”。

## 最新用户研究顺序

先多场景同题成败与轨迹 → 检查advantage的实际信息与分配 → 再讨论credit assignment → 必要时讨论reward shaping。拒答/幻觉惩罚等尚未实施。testbed为可选加分项，需新且不重叠数据；不能把已参与开发的E1重新命名为盲测。
