# 导师 10-31：过程信号、报告格式与优化器视角（匿名技术整理）

来源：项目提供的 Conversation，2026-10-31 段落。本页是技术性转述，不是逐字引语；个人身份与私聊的其他内容不公开。

## 工具与主动行为

- 不需要先把图片转成 OCR 文字描述。
- 训练中 base model 需要有主动行为：crop、zoom in、zoom out、verify、stop、recover 都算工具，OCR 也算工具。理由：大部分图像不是纯文字，有大量与最终目标无关的背景。

## 优化器与 advantage

- GRPO、DAPO 等只是作为 baseline 的 RL 优化器，不打算调整它们。
- 这些优化器的差别（例如 DAPO 的动态采样、更高的 clip 上限、token 限制、超长 shaping），最后都落实到 advantage 上；advantage 又和 reward、采样有关；有效梯度来自 advantage 前面的系数。改 reward 本身也是为了得到更好的 advantage。
- 梯度和三样东西强相关：advantage、新旧策略的重要性比率、clip（clip 只是防止更新偏离太远）。要从本质上理解更新的是什么、哪些需要更新，否则工程做法会变成盲目堆叠。
- 只改 reward 可以带来一些提升，但通常还需要配套的其他优化。

## 标注与奖励主次

- 可以给 benchmark 或语料补 bbox，但坐标要归一化。
- 任务奖励是主要的，必须保留；过程奖励可以另外构建。reward hacking 无法被平衡掉，但仍可以尝试 reward shaping。
- 改 reward 时可以考虑监督 bbox、约束工具使用，以此提供过程监督，但仍有 hacking 风险。

## 目标逼近与探索程度（导师的经验方案）

- 出发点：agent 行进过程中应当逼近目标——期望每一步都离目标更近，同时对整张图的探索程度增加。
- **目标逼近**：记录两个变量，“到第 t 步为止所有 crop 的框”和“目标框”。目标逼近信号 = maxIoU(目标框, 到第 t 步为止所有 crop 的框) + 目标框被覆盖的比例。
- **探索程度**：到第 t 步为止所有 crop 的框并起来覆盖的区域（当前 patch 与历史累积 patch 对整张图的覆盖比例）。
- **选择性地最大化两者**：
  - 前期 base model 一般裁不到合适区域，逼近分低，用探索程度作信号；
  - 中后期学会了合理的 crop 和其他工具，越来越逼近目标，用逼近分作信号；
  - 用一个触发 gate 在训练中切换两种信号。
- **两种信号不要做成加权和**：否则找到目标之后继续扫图仍能拿到探索分，相当于找到了还继续花额外成本。
- 这两个信号可以在给语料补充 bbox 后纳入 RL 训练阶段，导师预计会比较有效。

## baseline 与报告

- 导师提醒第一类（原模型 zero-shot）和第二类（SFT 后同样三项）baseline 要补齐，因为这两类跑得很快。（研究者此前已完成，见本库 `results/baseline_classes_20261031/`。）
- baseline 跑出来是什么就是什么；但 baseline 得 0 分可能是代码问题：选择题没有在 prompt 里约束输出选项，或者评测时匹配过松或过严，可以按这两点检查。
- 之后 RL 阶段的汇报只要三部分：
  1. 当前设定：SFT 语料的调整（如有）、RL 设置和参数；
  2. 定性 1–2 个 case study，加定量分数；
  3. 训练 log：reward、entropy、diff 曲线。
